<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Client Query Params -> Server | Query parameters `page` and `limit` are parsed from untrusted client URL |
| Database Error -> Client Response | Raw MySQL errors intercepted before returning to client |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-04 | Denial of Service | `server/src/utils/pagination.js` | medium | mitigate | Enforce strict upper bound `maxLimit = 50` so malicious requests cannot query `?limit=1000000` to exhaust server memory. |
| T-01-05 | Information Disclosure | `server/src/middleware/errorHandler.js` | high | mitigate | Strip internal database table schemas, SQL queries, and raw credentials from error responses returned to HTTP clients. |
| T-01-06 | Elevation of Privilege | `database/seeds/001_development_seeds.sql` | medium | mitigate | Clearly mark demo credentials for development only (`@demo.org`), enforce strong test passwords, and never run seed scripts in production. |
| T-01-SC | Supply Chain | Development Seeding Script | low | mitigate | Pure SQL file and `mysql2` parameterized execution; no external mocking libraries needed. |
</threat_model>
