  <files>server/src/db/migrate.js, server/package.json</files>
  <action>
    Create a standalone migration runner in `server/src/db/migrate.js` that connects via `server/src/config/db.js`.
    1. Ensure table `schema_migrations` exists (`id INT AUTO_INCREMENT PRIMARY KEY, name VARCHAR(255) NOT NULL UNIQUE, applied_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP`).
    2. Read all `.sql` files sorted alphabetically from `database/migrations/`.
    3. Query `schema_migrations` to find unapplied files.
    4. For each unapplied migration, execute the SQL statements inside a transaction or sequential statements, record the filename in `schema_migrations`, and log progress.
    5. Support `--status` flag to print migration status without executing.
    6. Add `"db:migrate": "node src/db/migrate.js"` and `"db:status": "node src/db/migrate.js --status"` to `server/package.json` scripts.
  </action>
  <verify>
    <automated>npm --prefix server run db:status</automated>
  </verify>
  <done>
    `npm run db:status` executes cleanly, verifies `schema_migrations` table existence, and reports migration status without errors.
  </done>

    3. `organizations`: `id`, `user_id` (FK to `users.id` ON DELETE RESTRICT UNIQUE), `name` (VARCHAR(255) NOT NULL), `mission` (TEXT), `description` (TEXT), `website` (VARCHAR(255)), `contact_email` (VARCHAR(255) NOT NULL), `phone` (VARCHAR(50)), `address` (VARCHAR(255)), `verification_status` (ENUM('pending', 'verified', 'rejected') NOT NULL DEFAULT 'pending'), `created_at`, `updated_at`.

    5. `opportunities`: `id`, `organization_id` (FK to `organizations.id` ON DELETE CASCADE), `category_id` (FK to `categories.id` ON DELETE RESTRICT), `title` (VARCHAR(255) NOT NULL), `description` (TEXT NOT NULL), `location_type` (ENUM('on-site', 'remote', 'hybrid') NOT NULL DEFAULT 'on-site'), `address` (VARCHAR(255)), `required_skills` (TEXT), `start_date` (DATE), `end_date` (DATE), `application_deadline` (DATETIME), `volunteer_capacity` (INT UNSIGNED), `status` (ENUM('draft', 'published', 'closed', 'archived') NOT NULL DEFAULT 'draft'), `created_at`, `updated_at`. Add indexes on `(status, application_deadline)`, `organization_id`, and `category_id`.
    6. `applications`: `id`, `opportunity_id` (FK to `opportunities.id` ON DELETE CASCADE), `volunteer_id` (FK to `users.id` ON DELETE CASCADE), `status` (ENUM('pending', 'accepted', 'rejected', 'withdrawn') NOT NULL DEFAULT 'pending'), `statement_of_interest` (TEXT), `availability_notes` (TEXT), `created_at`, `updated_at`. Enforce `UNIQUE KEY uq_opp_volunteer (opportunity_id, volunteer_id)` per REQ-APP-02.

    9. `user_achievements`: `id`, `user_id` (FK to `users.id` ON DELETE CASCADE), `achievement_id` (FK to `achievements.id` ON DELETE CASCADE), `earned_at` (DATETIME DEFAULT CURRENT_TIMESTAMP). Enforce `UNIQUE KEY uq_user_achievement (user_id, achievement_id)`.
    10. `contact_submissions`: `id`, `name` (VARCHAR(100) NOT NULL), `email` (VARCHAR(255) NOT NULL), `subject` (VARCHAR(255) NOT NULL), `message` (TEXT NOT NULL), `status` (ENUM('new', 'in_progress', 'resolved') NOT NULL DEFAULT 'new'), `created_at`.

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-01 | Tampering | `database/migrations/` | high | mitigate | Migration runner only executes `.sql` files from trusted repository migration directory in sorted sequential order. |
| T-01-02 | Denial of Service | `applications` table | high | mitigate | Enforce `UNIQUE KEY uq_opp_volunteer (opportunity_id, volunteer_id)` so duplicate concurrent application inserts fail immediately at database engine level. |
| T-01-03 | Information Disclosure | `server/src/db/migrate.js` | medium | mitigate | Never log raw database credentials in console outputs or error stacks; use sanitized error messages. |
| T-01-SC | Supply Chain | Database Migration Tooling | low | mitigate | Zero external migration dependencies added; uses existing `mysql2` and Node.js built-ins. |
